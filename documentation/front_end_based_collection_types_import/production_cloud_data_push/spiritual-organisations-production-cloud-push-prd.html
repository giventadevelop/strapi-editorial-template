3. Prerequisites

  1. Phase A complete: npm run import:spiritual-organisations -- --tenant-id=tenant_demo_002 --replace (18 rows; 11 with images in public/uploads/).
  2. .env: STRAPI_CLOUD_URL, STRAPI_CLOUD_API_TOKEN (Full Access).
  3. Deploy schema to Cloud so spiritual-organisation exists on production.
  4. Local Strapi dev server stopped before push.
  5. Cloud REST returns HTTP 200 on /api/spiritual-organisations.
Schema first: Deploy code to Strapi Cloud before running the push script, or creates will fail with HTTP 404.

5. REST verification (production)

GET {STRAPI_CLOUD_URL}/api/spiritual-organisations?filters[tenant][tenantId][$eq]=tenant_demo_002&sort=order:asc&populate[0]=tenant&populate[1]=image

6. Cloud image upload fix

When Cloud /api/upload fails (HTTP 500 / missing S3), use the migration image fix or S3 register path.

Finish Spiritual Organisations images on Cloud (migration)
npm run finish:collection-images-on-cloud -- --collection=spiritual-organisations --tenant-id=tenant_demo_002
S3 register + link (preferred when AWS on Cloud)
npm run push:collection-images-s3-to-cloud -- --collection=spiritual-organisations --tenant-id=tenant_demo_002 --skip-api
Order: (1) push:spiritual-organisations-to-cloud → (2) if images broken, push:collection-images-s3-to-cloud or finish:collection-images-on-cloud → (3) upgrade:cloud-media-urls-to-s3 if URLs still show /uploads/.
