2. Cloud payload fields

Fields sent in PUT/POST data object:

name, slug, excerpt, body, order, tenant — then separate PUT for image (numeric media id after upload).

3. Prerequisites

  1. Phase A complete: npm run import:catholicate -- --tenant-id=tenant_demo_002 --replace (local PRD).
  2. .env: STRAPI_CLOUD_URL, STRAPI_CLOUD_API_TOKEN (Full Access).
  3. Local Strapi dev server stopped (embedded Strapi loads local DB).
  4. Image files present under public/uploads/ (from local import).

4. Commands (Windows single-line)

npm run push:catholicate-to-cloud -- --tenant-id=tenant_demo_002
Images only (after Cloud upload works)
npm run push:catholicate-to-cloud -- --tenant-id=tenant_demo_002 --images-only
Verify on Cloud
node scripts/verify-catholicate-cloud.js

5. REST verification (production)

GET {STRAPI_CLOUD_URL}/api/catholicate-entries?pagination[pageSize]=100&populate[0]=tenant&populate[1]=image&filters[tenant][tenantId][$eq]=tenant_demo_002&sort=order:asc

Expect 9 entries; each tenant.tenantId = tenant_demo_002.

June 2026 — images fixed: 9 distinct images on Cloud via migration base64 upload. Frontend catholicate-cms shows unique card images.

5b. Cloud image upload fix

When POST /api/upload returns HTTP 500 on Cloud, use the migration image fix (not --images-only on push script).

Finish Catholicate images on Cloud
npm run finish:collection-images-on-cloud -- --collection=catholicate --tenant-id=tenant_demo_002
Images only (migration, manual)
npm run push:collection-images-migration -- --collection=catholicate --tenant-id=tenant_demo_002

Prerequisites: content on Cloud; migration code deployed; local Strapi stopped; images in public/uploads/.
