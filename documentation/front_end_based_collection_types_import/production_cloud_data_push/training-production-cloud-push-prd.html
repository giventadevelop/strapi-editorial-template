Push Directory – Training programs from local Strapi to Strapi Cloud. Status: Implemented.

Frontend route: /mosc-redesign/training

Strapi UID: api::training-program.training-program

REST plural: training-programs

Local CM: http://localhost:1337/admin/content-manager/collection-types/api::training-program.training-program

Cloud CM: {STRAPI_CLOUD_URL}/admin/content-manager/collection-types/api::training-program.training-program

Tenant: tenant_demo_002 · Upsert: slug + tenantId

3. Prerequisites

  1. Phase A complete: npm run import:training -- --tenant-id=tenant_demo_002 --replace (3 rows + images in public/uploads/).
  2. .env: STRAPI_CLOUD_URL, STRAPI_CLOUD_API_TOKEN (Full Access).
  3. Deploy schema to Cloud so training-program exists on production (npx strapi deploy --force or git push).
  4. Local Strapi dev server stopped before push (embedded Strapi loads local DB).
  5. Cloud REST returns HTTP 200 on /api/training-programs.
Schema first: Training is a new collection type. Deploy code to Strapi Cloud before running the push script, or creates will fail with HTTP 404.

4. Commands (Windows single-line)

Dry run

Push / update content + images
npm run push:training-to-cloud -- --tenant-id=tenant_demo_002
Images only (retry after Cloud upload fix)
npm run push:training-to-cloud -- --tenant-id=tenant_demo_002 --images-only

5. REST verification (production)

GET {STRAPI_CLOUD_URL}/api/training-programs?filters[tenant][tenantId][$eq]=tenant_demo_002&sort=order:asc&populate[0]=tenant&populate[1]=image

Expect 3 entries with slugs:

  • sruti-school-of-liturgical-music
  • divyabodhanam
  • st-basil-bible-school

6. Cloud image upload fix

After content push, use the migration image fix when Cloud /api/upload fails (HTTP 500 / missing S3).

Finish Training images on Cloud
npm run finish:collection-images-on-cloud -- --collection=training --tenant-id=tenant_demo_002
Order: (1) push:training-to-cloud → (2) deploy migration code if needed → (3) finish:collection-images-on-cloud --collection=training.
