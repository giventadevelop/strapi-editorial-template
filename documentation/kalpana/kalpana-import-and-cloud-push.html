Kalpana Downloads – Import & Cloud Push PRD

End-to-end guide for Downloads – Kalpana Editions and Downloads – Kalpana Documents (PDFs): local import from mosc.in / mosc-temp, then push to Strapi Cloud. Status: Scripts complete (June 2026 — proven on tenant_demo_002 and mosc_malankara_orthodox_2).

Two collection types + one single type:

Admin (local)Strapi UIDREST pluralMedia field
Kalpana Editions api::kalpana-edition.kalpana-edition kalpana-editions cardImage (thumbnail)
Kalpana Documents api::kalpana-document.kalpana-document kalpana-documents pdf
Kalpana Page (single type) api::kalpana-page.kalpana-page — hero images on page

Default tenant: tenant_demo_002 · Upsert keys: editions = slug + tenantId; documents = sourceUrl + tenant (fallback slug + tenant)

Import order: Editions first → Documents second (documents relate to an edition by slug).

Run editions before documents. Document import resolves edition relation by matching edition slug (e.g. kalpana-2026). If editions are missing, documents are skipped or orphaned.

3. Phase B – Cloud push

3.1 One-command orchestrator (recommended first time)

Probes Cloud for Kalpana schema, optionally deploys config, then pushes editions → documents → page.

Complete Kalpana Cloud import
$env:NODE_TLS_REJECT_UNAUTHORIZED='0'; npm run complete:kalpana-cloud-import -- --tenant-id=tenant_demo_002 --skip-deploy

Use --skip-deploy when schema is already on Cloud (npx strapi login + npm run deploy done). Without it, script tries transfer token or CLI deploy.

4. Prerequisites

  1. Phase A complete for the target tenant (editions + documents visible in local admin URLs above).
  2. .env: STRAPI_CLOUD_URL, STRAPI_CLOUD_API_TOKEN (Full Access).
  3. Stop local Strapi dev server before Cloud push scripts (embedded Strapi loads SQLite).
  4. PDF/image files under public/uploads/ and/or scripts/data/kalpana-pdfs/.
  5. Kalpana content types deployed on Cloud (/api/kalpana-editions returns 200, not 404).
  6. For Cloud fetch on Windows: $env:NODE_TLS_REJECT_UNAUTHORIZED='0' if TLS errors occur.

5. Cloud image / PDF upload fix

Kalpana uses non-standard media fields. Do not use image in REST PUT for these types.

Registry keymediaFieldFinish command
kalpana-editions cardImage npm run finish:collection-images-on-cloud -- --collection=kalpana-editions --tenant-id=TENANT
kalpana-documents pdf npm run finish:kalpana-documents-on-cloud -- --tenant-id=TENANT
Known issue (June 2026): Migration endpoint may report Created: N | Linked: N but REST verification shows all media MISSING. Morph DB link does not surface on Strapi 5 REST. Workaround: REST PUT via scripts/lib/link-cloud-images-rest.js with correct mediaField. See image migration fix §5.
Finish edition thumbnails on Cloud
$env:NODE_TLS_REJECT_UNAUTHORIZED='0'; $env:TENANT_ID='tenant_demo_002'; npm run finish:collection-images-on-cloud -- --collection=kalpana-editions --tenant-id=tenant_demo_002
Finish document PDFs on Cloud
$env:NODE_TLS_REJECT_UNAUTHORIZED='0'; $env:TENANT_ID='tenant_demo_002'; npm run finish:kalpana-documents-on-cloud -- --tenant-id=tenant_demo_002
TENANT_ID env: If TENANT_ID=tenant_demo_002 is in .env but you push another tenant, set $env:TENANT_ID='your_tenant' before finish scripts.

6. REST verification (Cloud)

Editions (~12 per tenant):

GET {STRAPI_CLOUD_URL}/api/kalpana-editions?pagination[pageSize]=20&populate[0]=cardImage&populate[1]=tenant&filters[tenant][tenantId][$eq]=tenant_demo_002&sort=year:desc

Documents (~350 per tenant):

GET {STRAPI_CLOUD_URL}/api/kalpana-documents?pagination[pageSize]=5&populate[0]=pdf&populate[1]=tenant&populate[2]=edition&filters[tenant][tenantId][$eq]=tenant_demo_002

Expect non-null cardImage.url on editions and pdf.url on documents.

Documents import skips rows Edition slugs missing locally Run import:kalpana first with --replace
Invalid key image on Kalpana PUT REST linker used image instead of cardImage / pdf Use updated link-cloud-images-rest.js (June 2026 fix)
Finish script targets wrong tenant TENANT_ID in .env Set $env:TENANT_ID explicitly
PDF upload fails on Cloud POST /api/upload / S3 misconfig Use migration base64 path (image fix doc) or --pdfs-only retry
Kalpana page wrong after clone Single type — one per instance push:kalpana-page-to-cloud separately; not included in tenant clone
