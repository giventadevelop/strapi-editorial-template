Lectionary PDF → Excel & Strapi Import

This document describes the input PDFs for the liturgical calendar, how their content maps to Excel columns and Strapi fields, and the scripts used to delete, import, and export liturgy-day data. The PDF-based import replaces the earlier seed script for bulk data.

0. Standard parameters (tenant, year, excel, editor)

⚙️ Shared CLI parameters

All liturgy scripts use the shared module scripts/lib/liturgy-cli.js. Pass these four parameters on the command line or via environment variables. Year-based defaults resolve PDF and Excel paths under documentation/lectionary_calendar/.

ParameterCLI flagEnvironment variableDefault / notes
Tenant ID--tenant-id=XXXTENANT_ID, LITURGY_TENANT_IDRequired for import, sync, Malayalam update, cloud push (optional = all tenants on push)
Year--year=YYYYYEAR, LITURGY_YEAR2026; drives PDF names and Liturgy-Days-Malayalam-{year}.xlsx
Malayalam Excel--excel=pathLITURGY_MALAYALAM_EXCEL, LITURGY_EXCELLiturgy-Days-Malayalam-{year}.xlsx when omitted
Editor email--editor-email=...LITURGY_EDITOR_EMAIL, EDITOR_EMAILVerify script only; positional email still works

Year-based file names (example for --year=2026):

  • English PDF: 2026-Liturgical-Calender.pdf
  • Malayalam PDF: Panjangom_26.pdf
  • Malayalam Excel: Liturgy-Days-Malayalam-2026.xlsx
  • Master Excel: Liturgy-Days-Master-2026.xlsx

Dry run: prefix with DRY_RUN=1 (PowerShell: $env:DRY_RUN=1; node scripts/...). Clear with Remove-Item Env:DRY_RUN before real runs.

1. Input PDFs (which is which)

📄 Source files

Two PDFs in documentation/lectionary_calendar/ are the input data. The parser and import scripts use them as follows.

FileLanguageUse
2026-Liturgical-Calender.pdf English Day headings (e.g. “New Year. Circumcision of our Lord…”), season codes (Niram N). One entry per calendar day in format N. Description.
Panjangom_26.pdf Malayalam Same structure: day number + description. Season codes appear as (\ndw N). Merged with English by date.

Entries are merged by date (YYYY-MM-DD). Month is inferred from the order of days (day 1 starts a new month). If a date exists only in one PDF, that row keeps the other language fields empty until filled by carry-over or backfill where applicable.

2. PDF → Excel / Strapi column mapping

⚙️ Column mapping

Each parsed liturgy day becomes one row in Excel and one Strapi document. English and Malayalam columns are on the same row (not repeated rows per language).

Excel / Strapi fieldSourceNotes
dateParsed from both PDFsYYYY-MM-DD; inferred from day number and month order.
dayHeadingEnEnglish PDFText after N. for that date (continuation lines merged).
dayHeadingMalylmMalayalam PDFText after day number for same date (merged by date).
seasonNameEnExtracted from EN heading(Niram N) → “Niram N”; else carry-over from previous day or backfill.
seasonNameMalylmExtracted from ML heading(\ndw N) → “Niram N”; else carry-over / backfill.
orderImport script0-based index of the day in the created set.
readings—PDFs do not list readings; array is empty. Excel columns reading1_*, reading2_* are for manual or future data (e.g. liturgyHeadingEn, liturgyHeadingMalylm, contentPlaceEn, contentPlaceMalylm).

Excel template columns for readings (when populated from another source): reading1_liturgyHeadingEn, reading1_liturgyHeadingMalylm, reading1_contentPlaceEn, reading1_contentPlaceMalylm, and similarly reading2_*. These are not filled by the PDF parser.

3. Delete liturgy days (purge)

📋 Delete script

Use delete-liturgy-days.js to remove liturgy-day entries before re-importing. With no tenant ID, it deletes all liturgy days (all tenants). With --tenant-id=..., it deletes only that tenant’s entries.

Purge liturgy days
🔧 Customize parameters
node scripts/delete-liturgy-days.js --tenant-id=tenant_demo_002
Windows single-line:
node scripts/delete-liturgy-days.js --tenant-id=tenant_demo_002
Note: Omit --tenant-id to delete all liturgy days across tenants. Use DRY_RUN=1 to only log the count without deleting.

4. Import from PDF into Strapi

📋 Import script

Use import-liturgy-days-from-pdf.js to parse the two PDFs and create liturgy-day documents in Strapi for a tenant.

Import from PDF
🔧 Customize parameters
node scripts/import-liturgy-days-from-pdf.js --tenant-id=tenant_demo_002 --year=2026 --limit=10
Windows single-line:
node scripts/import-liturgy-days-from-pdf.js --tenant-id=tenant_demo_002 --year=2026 --limit=10

Options:

  • --tenant-id=... — Tenant to attach entries to (default: tenant_demo_002).
  • --year=YYYY — Calendar year for parsed dates (default: 2026).
  • --limit=N — Create at most N entries (for testing).
  • DRY_RUN=1 — Parse and log only; do not create.
  • --dump-text — Write raw PDF text to dumped-en.txt / dumped-ml.txt.
  • --en-pdf=path / --ml-pdf=path — Override PDF paths.

5. Export parsed PDF to Excel

📊 Export to Excel

To get the same parsed data into an Excel sheet (e.g. for review or editing), use export-liturgy-days-from-pdf-to-excel.js. It runs the same parser as the import script and writes all merged days to documentation/lectionary_calendar/liturgy-days-from-pdf.xlsx with columns aligned to the mapping above.

Export PDF → Excel
🔧 Customize parameters
node scripts/export-liturgy-days-from-pdf-to-excel.js --year=2026
Windows single-line:
node scripts/export-liturgy-days-from-pdf-to-excel.js --year=2026

Output file: documentation/lectionary_calendar/liturgy-days-from-pdf.xlsx. Reading columns are present but empty (PDFs do not contain per-day readings).

6. Wrong data: what went wrong and the fix

This section records a real remediation (June 2026): incorrect English and Malayalam liturgical calendar data on local and Strapi Cloud, what caused it, and the correct scripted sequence that fixed it.

What went wrong
SymptomLikely cause
Cloud: 2,645 liturgy-day rows (many per date; many with no tenant)Repeated PDF imports and/or --split-en-headings (one row per English sentence on the same date); pushing without purging Cloud first; tenant relation not set on some creates.
Local: 166 rows, incomplete year (Jan–Sep only)PDF import alone — English PDF parser does not cover Oct–Dec reliably.
Malayalam gibberish or wrong script on some rowsPDF parser encoding on Malayalam PDF text; those rows were never replaced because the wrong script was used (see below).
Only ~120 Malayalam rows updated; 67 Excel dates skippedUsed update-liturgy-days-malayalam-from-excel.js alone — it only updates dayHeadingMalylm on existing DB rows by date; it does not create Oct–Dec rows or remove PDF-only extras.
Editors see 0 entries while superadmin sees hundredsContent missing tenant relation, or Editor Tenant Assignment not on Cloud; see liturgy-days-tenant-relation-fixes.html.
Do not use for a full calendar fix:
  • update-liturgy-days-malayalam-from-excel.js without sync-liturgy-days-from-malayalam-excel.js --prune-not-in-excel afterward.
  • --split-en-headings on PDF import (multiplies rows per date).
  • Repeated import/push without purge (duplicates on Cloud).
  • npm run push:rest-to-cloud for liturgy-only fixes when Cloud already has other content — use push-liturgy-days-to-cloud.js instead.
The fix (correct pipeline)

Authoritative Malayalam source: Liturgy-Days-Malayalam-2026.xlsx (185 unique feast dates). After PDF import + Excel sync with --prune-not-in-excel, expect 185 rows for tenant_demo_002, one per date, UTF-8 Malayalam.

Local rebuild only (verified June 2026 — no Cloud push):

node scripts/delete-liturgy-days.js --tenant-id=tenant_demo_002
node scripts/import-liturgy-days-from-pdf.js --tenant-id=tenant_demo_002 --year=2026
node scripts/sync-liturgy-days-from-malayalam-excel.js --tenant-id=tenant_demo_002 --prune-not-in-excel
node scripts/verify-editor-tenant-liturgy.js --tenant-id=tenant_demo_002 --year=2026

Observed results (local): purge 166 → PDF import 166 created (167 merged PDF days; 1 invalid date 2026-06-31) → sync: updated 120, created 65, pruned 46 PDF-only extras → 185 total for tenant.

Local + Cloud (when Cloud also needs reset):

node scripts/clear_cloud_data.js --remote --types=liturgy-days
node scripts/delete-liturgy-days.js --tenant-id=tenant_demo_002
node scripts/import-liturgy-days-from-pdf.js --tenant-id=tenant_demo_002 --year=2026
node scripts/sync-liturgy-days-from-malayalam-excel.js --tenant-id=tenant_demo_002 --prune-not-in-excel
node scripts/push-liturgy-days-to-cloud.js --tenant-id=tenant_demo_002
node scripts/verify-editor-tenant-liturgy.js --tenant-id=tenant_demo_002 --year=2026

Observed results (Cloud, earlier full remediation): Cloud purge 2,645 deleted → push 185 created on Cloud. Always pass --remote and --types=liturgy-days to clear_cloud_data.js so other collection types are not deleted.

Script roles:
  • import-liturgy-days-from-pdf.js — English (+ PDF Malayalam) baseline; ~166 rows; no --split-en-headings.
  • sync-liturgy-days-from-malayalam-excel.js --prune-not-in-excel — required for full year + clean Malayalam; creates missing dates, updates Malayalam, removes PDF-only rows.
  • update-liturgy-days-malayalam-from-excel.js — optional overlay only when DB dates already match Excel; not sufficient alone.

7. Run order (full remediation workflow)

Orphaned records: If liturgy days were imported without a tenant link (e.g. after copying db_backup/data.db from another machine), verify-editor-tenant-liturgy.js may show 0 days for your tenant even though hundreds exist in the database. In that case use node scripts/delete-liturgy-days.js --all (not only --tenant-id=...) before re-importing.
  1. Stop the Strapi server if it is running.
  2. Audit (optional): node scripts/verify-editor-tenant-liturgy.js mosc.regular.user@keleno.com tenant_demo_002
  3. Preview import (optional): PowerShell $env:DRY_RUN=1; node scripts/import-liturgy-days-from-pdf.js --tenant-id=tenant_demo_002 --year=2026 then Remove-Item Env:DRY_RUN before the real import.
  4. Delete liturgy days: node scripts/delete-liturgy-days.js --tenant-id=tenant_demo_002 or node scripts/delete-liturgy-days.js --all when records have no tenant.
  5. Import from PDF (do not use --split-en-headings): node scripts/import-liturgy-days-from-pdf.js --tenant-id=tenant_demo_002 --year=2026
  6. Excel sync (required for full calendar) — creates Oct–Dec + missing dates, prunes PDF-only rows, sets Malayalam from Excel: node scripts/sync-liturgy-days-from-malayalam-excel.js --tenant-id=tenant_demo_002 --prune-not-in-excel (see section 9). Do not stop after PDF import alone.
  7. Malayalam overlay only (optional, not sufficient alone): node scripts/update-liturgy-days-malayalam-from-excel.js --tenant-id=tenant_demo_002 --year=2026 — use only when dates already exist in DB; see section 6.
  8. Verify again with verify-editor-tenant-liturgy.js (see section 8).
  9. Start Strapi and spot-check Content Manager and the frontend calendar.
  10. Cloud sync (optional, liturgy-only): see section 10.
Expected counts (2026 feast-day calendar, not 365 civil days): Malayalam Excel has 185 unique feast dates (2026-01-01 through 2026-12-27). After PDF import + Excel sync with --prune-not-in-excel, expect 185 DB records and 0 gibberish Malayalam. PDF import alone yields ~166 rows through September only.

10. Push to Strapi Cloud (liturgy only)

Protect other Cloud content: When Strapi Cloud already has articles, media, tenants, and other collection types, use only push-liturgy-days-to-cloud.js. Do not run npm run push:rest-to-cloud or npm run strapi transfer unless you intend to replace the entire Cloud database.
Safe liturgy-only push

The script reads local liturgy days and upserts on Cloud by date + tenant. It calls only /api/liturgy-days and may create missing tenants on Cloud. It does not modify articles, events, or any other collection type.

Push liturgy days to Cloud
🔧 Customize parameters
node scripts/push-liturgy-days-to-cloud.js --tenant-id=tenant_demo_002
Windows single-line:
node scripts/push-liturgy-days-to-cloud.js --tenant-id=tenant_demo_002
  1. Ensure STRAPI_CLOUD_URL and STRAPI_CLOUD_API_TOKEN are set in .env.
  2. Stop local Strapi. Preview with $env:DRY_RUN=1; node scripts/push-liturgy-days-to-cloud.js --tenant-id=tenant_demo_002
  3. On Windows, if you see unable to verify the first certificate, run once with $env:NODE_TLS_REJECT_UNAUTHORIZED="0" before the push command.
  4. Confirm Cloud Admin → Editor Tenant Assignment for editor email + tenant, then have editors re-login.

Example result (May 2026): Created: 65, Updated: 120 — 185 liturgy days on Cloud; no other collection types touched.

12. Do not copy SQLite for liturgy data

Why db_backup/data.db is the wrong fix

Copying db_backup/data.db from another machine often causes:

  • Liturgy days with no tenant link (verify shows 0 for your tenant).
  • Duplicate rows for the same dates.
  • Gibberish Malayalam in dayHeadingMalylm (PDF encoding) mixed with correct UTF-8 rows.
  • Missing or truncated date ranges.

Correct approach: purge with delete-liturgy-days.js, re-import with import-liturgy-days-from-pdf.js, then Excel sync with sync-liturgy-days-from-malayalam-excel.js --prune-not-in-excel (not overlay-only). Verify, then optionally push with push-liturgy-days-to-cloud.js. See section 6 and Liturgy Days – Tenant Relation Fixes.
